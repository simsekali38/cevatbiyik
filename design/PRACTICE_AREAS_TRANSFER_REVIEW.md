## Model gaps reported before implementation

Scope and approach do not have separate fields: use the existing Admin content editor to supply
reviewed h2/h3 sections. The view does not synthesize headings or split arbitrary HTML.
PracticeAreaDto/controller supply no related FAQ/article collections; FaqItem has no area link.
These sections are absent instead of empty cards. A subsequent separately authorized task could
reuse published-article filtering in the controller and design an explicit FAQ relationship.
No such backend work was included here.

Observed legacy-data limitation: an active row inserted outside normal CMS validation with
CONTENT_REQUIRED in its description still uses that value in existing SEO metadata. This task
hides it in visible view content only and intentionally preserves SEO/controller behavior.
Normal CMS validation rejects publishing this value. Review/clean legacy data in Admin;
a metadata fallback improvement should be a separately scoped follow-up.
